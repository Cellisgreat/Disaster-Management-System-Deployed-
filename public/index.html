How it works

Report → allocate → dispatch → close

A single request triggers the whole pipeline: the graph is searched, the closest suitable volunteers are reserved, and every change is written straight back to the CSV databases.

The citizen reports

Choose a service category (Rescue, Medical Help or Food), the affected area and how many people need help.

C++ allocates

Volunteers already in the area are dispatched first. Then Dijkstra's algorithm finds the nearest suitable volunteers in other areas.

Availability updates

Assigned volunteers are marked unavailable, coverage is recorded per request and the databases are saved atomically.

Operations close the case

When work is finished an administrator marks the request completed and the volunteers return to the available pool.
